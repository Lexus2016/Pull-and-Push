# Updates from GitHub, notifications, settings

### Updates — straight from GitHub
- **The app updates itself.** Once a day it checks this repository's latest release and offers *Install and Relaunch* (or **Pull-and-Push ▸ Check for Updates…**). Every update is EdDSA-signed, the feed is signed too, and the new app must carry the same Developer ID — a tampered file or feed is refused.
- If research is running when you install, the app asks first, stops the agents cleanly and keeps everything saved; choose *When I Quit* to install later.
- Installs from source get a **⬆ vX** badge in the dashboard when a new release is out (`git pull && ./start.sh --update`); the daily check can be switched off in Settings.
- v0.3.0 has no updater yet: download this DMG once, the next versions arrive by themselves.

### Notifications
- When a run reaches its target, stops (no more progress, budget, iteration limit), fails or waits for your decision, macOS tells you — click the notification to open that project. The app asks for permission the first time a run starts.

### Settings & diagnostics (⚙, or ⌘, in the app)
- Agent CLIs with their versions and paths (and the install command for a missing one), git, Docker.
- **Python for scorers:** `{python}` can now point at your own interpreter (numpy, pandas …) instead of the bundled, standard-library-only one — pick one of the detected Pythons or enter a path. `PULL_AND_PUSH_PYTHON` overrides it.
- Version and update status, the data folder, security status; **Copy diagnostics** for bug reports.

### Security
- The terminal dashboard now needs a token too (it could be reached by other local users). The printed link signs your browser in once and is traded for an HttpOnly, SameSite=Strict cookie — the token leaves the address bar, and the plain `http://127.0.0.1:8765/` bookmark keeps working. Lost the link? `pull-and-push url --open`. `--no-auth` restores the old behaviour.

### For automation
- `pull-and-push url` — the running dashboard's sign-in link.
- `GET /api/diagnostics`, `GET /api/runs/events?since=N` (runs that ended: status, reason, best vs target, cost).
- `macos/release.sh` — one command: build, notarize, sign for Sparkle, publish atomically (draft → verify → publish).
