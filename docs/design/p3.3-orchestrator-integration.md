# P3.3 — Orchestrator integration (design + plan)

Status: **design**. Final sub-phase of [`p3-scoring-core.md`](./p3-scoring-core.md). Wires the
P3.1 engine + P3.2 sandbox into the existing optimization loop with **zero orchestrator changes**.

Brand note: the CLI command is **`pull-and-push`** (primary console-script; `tyani-tolkai` is a
back-compat alias; the Python package stays `tyani_tolkai`). All user-facing examples use
`pull-and-push`.

## Decision — reuse the `numeric` adapter, add one CLI command

The `numeric` metric adapter already runs `evaluation.command` in the artifact dir and parses a
JSON object from its stdout (`data[metric.name]` per configured metric). `score_bot_sandboxed`
already returns exactly such a metrics dict. So the integration is just a CLI command that prints
that dict — no new adapter, no orchestrator surgery:

```
pull-and-push score-bot --data <ohlcv.csv> --bot-dir <dir> --bot-cmd "<cmd>" --seed <s>
```
prints `{"return_oos_pct": .., "liquidations": .., ...}` to **stdout only**; a project config then
uses:
```yaml
evaluation:
  adapter: numeric
  command: 'pull-and-push score-bot --data ../metrics/data.csv --bot-dir . --bot-cmd "python bot.py" --seed <project-seed>'
  metrics:
    - {name: return_oos_pct, dir: higher, weight: 0.5, target: 100}
    - {name: liquidations,   dir: lower,  weight: 0.2, target: 0}
    - {name: max_drawdown_pct, dir: lower, weight: 0.2, target: 30}
```
The optimizer edits the bot in the artifact dir; each iteration the harness command runs the bot
in the Docker sandbox and the engine scores it. The held-out data lives beside the harness, never
inside the container.

## Contract details (so it plugs into `numeric`)
- **stdout = ONLY the JSON metrics dict.** No log lines, no "wrote ..." — the adapter does
  `json.loads(stdout)`. Diagnostics go to **stderr**.
- **Non-zero exit on failure.** `SandboxUnavailable` / `BotProtocolError` → message to stderr,
  exit code 1 → the numeric adapter sees `exit_code != 0` → `MetricResult(ok=False)` (a failed
  evaluation, not a crash of the loop).
- Bars loaded from a CSV with header `time,open,high,low,close,volume`; the `time` column is
  DROPPED → engine bars are `(o,h,l,c,v)` (consistent with P3.1's anti-exfiltration choice).

## Plan (TDD)

### Task 1: `load_bars_csv`
**Files:** `src/tyani_tolkai/bot_io.py` (create), `tests/test_bot_io.py` (create).
- `load_bars_csv(path) -> list[tuple]`: `csv.DictReader`; each row → `(open, high, low, close, volume)`
  floats (drop `time`; missing/empty volume → 0.0). Raise `ValueError` on a missing OHLC column.
- Tests: a 3-row CSV → 3 five-tuples, time dropped, values correct; missing-volume → 0.0; a CSV
  missing `close` → ValueError.

### Task 2: `score-bot` CLI subcommand
**Files:** `src/tyani_tolkai/cli.py` (modify), `tests/test_cli_score_bot.py` (create).
- Module-level alias imports (for monkeypatching): `from .bot_sandbox import score_bot_sandboxed as
  _score_bot_sandboxed, SandboxUnavailable`; `from .bot_runner import BotProtocolError`;
  `from .bot_io import load_bars_csv`.
- `cmd_score_bot(args) -> int`: validate `--data` and `--bot-dir` exist (else stderr + exit 2);
  `bars = load_bars_csv(args.data)`; `params = json.loads(args.params) if args.params else {}`;
  `bot_cmd = shlex.split(args.bot_cmd)`; call `_score_bot_sandboxed(bot_cmd, bars, bot_dir=...,
  seed=args.seed, params=params, per_read_timeout=..., total_timeout=...)`; on
  `(SandboxUnavailable, BotProtocolError)` → stderr + return 1; else `print(json.dumps(metrics))`
  (stdout only) + return 0.
- subparser `score-bot`: `--data` (req), `--bot-dir` (req), `--bot-cmd` (req, shlex-split),
  `--seed` (req), `--params` (JSON str, optional), `--per-read-timeout` (float, default 10),
  `--total-timeout` (float, default 120). `set_defaults(func=cmd_score_bot)`.
- Tests (`test_cli_score_bot.py`):
  - unit (monkeypatch `cli._score_bot_sandboxed` to return a canned metrics dict): `main(["score-bot",
    "--data", csv, "--bot-dir", d, "--bot-cmd", "python b.py", "--seed", "s"])` → exit 0 AND stdout
    is exactly the JSON dict (parse it back, assert equals canned). Assert NOTHING else on stdout.
  - missing data → exit 2; missing bot-dir → exit 2.
  - error path (monkeypatch to raise BotProtocolError) → exit 1, stderr non-empty, stdout empty.
  - docker-gated end-to-end (skipif not docker_available): write the self-contained refbot + a tiny
    CSV, run `main(["score-bot", ...])` for real → exit 0, stdout parses to a dict containing
    `return_oos_pct`.
- Then full suite: P1/P2/P3.* green; 48 pre-existing PyPy/sqlite failures unrelated.

## Done criteria
- `pull-and-push score-bot ...` prints a metrics JSON dict (stdout only) for a sandboxed bot, and
  fails cleanly (stderr + non-zero) so the `numeric` adapter records a failed evaluation.
- Documented config wiring uses `adapter: numeric` + the `score-bot` command — no orchestrator code
  changed.

## Out of scope (P4+)

adapter; ≥2-run determinism enforcement in config; the intent-first UI (P5).
